## 💡 设计理念（当前实现版）

### 2.1 轻量优先原则

> 「够用就好，渐进增强」

与设计文档的完整版相比，当前版本的设计原则：

1. **最小依赖原则** - 只引入真正需要的依赖
2. **基础功能先行** - 先跑通核心流程，再扩展高级功能
3. **易于维护** - 代码结构清晰，新手也能看懂
4. **渐进式重构** - 在运行中优化，而不是追求完美架构

### 2.2 当前技术选型的思考

**为什么是 Naive UI 而不是 Element Plus？**
- 更好的 Vue 3 Composition API 原生支持
- 主题定制更灵活
- 包体积更小，Tree Shaking 更彻底
- 类型定义更完善

**为什么现阶段用 localStorage？**
- 实现简单，开箱即用
- 足够支撑 < 1000 条数据的小团队
- 未来可平滑迁移到 IndexedDB

**为什么还没加那些"高级功能"？**
> YAGNI 原则 - You Aren't Gonna Need It
- 先确保核心功能稳定可用
- 复杂度是逐步增加的，不是一蹴而就的
- 过早优化是万恶之源

## ⚠️ 已知限制与注意事项

### 6.1 当前版本限制

| 限制 | 影响 | 计划解决 |
|------|------|---------|
| localStorage 5MB 容量限制 | 数据量 > 1000 条可能有问题 | 下一阶段迁移到 Dexie.js |
| 没有真实后端 | 多设备间数据无法同步 | 远期可选项 |
| Mock 数据写死在代码中 | 每次发布可能重置用户数据 | 立即修复，分离到 mocks 目录 |
| 没有批量导入导出 | 无法备份数据 | 本月实现 |
| 表格没有虚拟滚动 | > 100 行可能出现卡顿 | 启用 Naive UI 内置虚拟滚动 |
